## About

This is my personal portfolio website, built to bring together my two main creative and technical interests: **software development and photography**.

The website includes a dedicated developer section for my software projects as well as a photography gallery showcasing selected work and camera information.

The goal was to create a portfolio that feels personal and visually distinctive while remaining fast, responsive and accessible.

## Features

- Bilingual content in English and German
- Dedicated developer portfolio
- Photography gallery with a keyboard-accessible modal viewer
- Responsive desktop and mobile layouts
- Custom animations and scroll interactions
- Reduced-motion support
- Semantic and keyboard-accessible interface
- Custom design system using hand-written CSS
- Self-hosted fonts and icons, so no third-party requests at runtime
- Per-route metadata and a real HTTP 404 for unknown paths
- Static deployment without a backend

```text
src/
├── components/

│   └── layout/
├── data/          routes.js, photos.js, legal.js, navigation.js
├── pages/
├── styles/

public/
├── fonts/         self-hosted woff2 (Mona Sans, Inter)
└── images/
    ├── logos/
    ├── icons/     technology icons (Devicon, MIT)
    ├── projects/
    ├── gallery/
    └── placeholders/

scripts/
└── verify-build.mjs   post-build checks, also run in CI

docs/
├── jpg-portfolio-logo.webp
└── portfolio-preview.webp
```

The project is separated into reusable components and dedicated data files for
projects, navigation, photography content and legal pages.

[`src/data/routes.js`](src/data/routes.js) is the single source of truth for
routes: the build generates one HTML file per entry, the client router maps
paths to pages from it, and the sitemap is derived from it.

## Design and Accessibility

The portfolio was designed from scratch with a strong focus on typography, spacing and visual hierarchy.

Accessibility considerations include:

* Semantic HTML structure
* Keyboard-accessible interactive elements
* Visible focus states
* Responsive layouts
* Support for `prefers-reduced-motion`

Animations and parallax effects are reduced when the user's operating system requests less motion.

## Development

Requires Node **20.19+** or **22.12+** (the range Vite 7 supports);
[`.nvmrc`](.nvmrc) pins the version used in CI.

```bash
npm install
npm run dev       # http://localhost:5173
npm run lint      # ESLint, including the rules of hooks
npm run build     # production build into dist/
npm run check     # lint + build

node scripts/verify-build.mjs      # verify dist/ (routes, metadata, assets)
node scripts/make-thumbnails.mjs  # regenerate gallery thumbnails (needs ffmpeg)
```

### Gallery images

Originals live in `public/images/gallery/large/` and are what the lightbox
loads. The grid loads downscaled copies from `public/images/gallery/thumbnails/`,
generated by `scripts/make-thumbnails.mjs` and committed alongside the
originals — so neither the build nor CI needs ffmpeg. After adding or replacing
a photo, run that script; `verify-build.mjs` fails if a thumbnail is missing.

## Deployment

The production website is deployed on **Vercel** and available at:

**https://jaygrenacher.ch**

The application is built as a static frontend and does not require a backend or database.

### Routing

The build writes one HTML file per route (`index.html`, `developer.html`,
`gallery.html`, `datenschutz.html`, `impressum.html`, `404.html`). With
Vercel's `cleanUrls`, `/developer` is served directly from `developer.html`,
so a direct request, a refresh or a shared link is an ordinary 200 with no SPA
rewrite involved — and an unknown path falls through to `404.html` with a real
HTTP 404 instead of quietly returning the homepage.

Each generated file carries its own `title`, `description`, canonical URL and
Open Graph tags, so crawlers and social scrapers — which do not run the
client-side router — read the correct metadata for the page they requested.

### Security headers

[`vercel.json`](vercel.json) sets a Content-Security-Policy alongside HSTS,
`X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`,
`Permissions-Policy` and the cross-origin policies. Every script, style, font
and image is served from this origin, so the policy needs no third-party
allowances.
